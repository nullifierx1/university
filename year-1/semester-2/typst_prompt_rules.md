# Общие правила для Typst-файлов

Используй эти правила при написании любого `.typ`-файла: домашка, отчёт, доказательства, конспект, матан, дискретка, лабораторная. Цель: файл должен нормально рендериться в PDF, выглядеть аккуратно и не иметь искусственного AI-стиля.

## 1. Общий стиль файла

- Пиши на русском, если я отдельно не попросил другой язык.
- Не делай текст стерильным и одинаковым. Пусть пункты отличаются по длине, началу и структуре.
- Не растягивай простые места. Если мысль короткая, пиши коротко.
- Не начинай каждый пункт одинаково: «Рассмотрим», «Заметим», «Для начала», «В данном случае».
- Не используй искусственную структуру в каждом пункте вида «Утверждение → Решение → Ответ → Обоснование».
- Не добавляй формальные определения там, где достаточно нормального объяснения.
- Не пиши слишком гладко и шаблонно. Лучше естественный учебный текст, чем канцелярит.
- Избегай слов и фраз: «данный», «соответствующий», «очевидно», «тривиально», «нетрудно видеть», «в рамках», «таким образом» слишком часто, «важно отметить», «стоит отметить».
- Если нужен итог, пиши `*Ответ:* ...`, но не обязательно в каждом пункте.

## 2. Структура Typst

- Основные задания оформляй через `+`.
- Подпункты `(a), (b), (c)` оформляй через:

```typst
#enum(numbering: "(a)", full: false, spacing: 12pt)[
  ...
][
  ...
]
```

- Не смешивай `+` и `#enum` на одном уровне вложенности.
- Пустая строка в `.typ` — это новый абзац.
- `\\` используй только при реальной необходимости. Не ставь принудительный перенос после каждой строки.
- `#pagebreak()` используй только между крупными блоками, а не после каждого задания.
- Жирный текст `*...*` используй умеренно: для `*Ответ:*`, `*База:*`, `*Переход:*`, `*Идея:*`, важных итогов.
- Не делай слишком много заголовков на маленьких кусках текста.

## 3. Inline math и block math

- Короткие формулы пиши inline: `$2^n - 1$`, `$a_n$`, `$x_i >= 0$`.
- Не выноси короткую формулу в отдельный блок, если она спокойно читается в строке.
- Блочную формулу используй только для длинных выражений, цепочек преобразований, систем, важных итогов или громоздких формул.
- Не ставь точку внутри блочной формулы.

Плохо:

```typst
$
a_n = 2^n - 1.
$
```

Хорошо:

```typst
$
a_n = 2^n - 1
$
```

Или inline:

```typst
Получаем $a_n = 2^n - 1$.
```

## 4. Скобки в дробях

Всегда бери длинный числитель и знаменатель в скобки. Это защищает от сломанного отображения и неправильного смысла.

Плохо:

```typst
$x^2/1 - x$
$1 - x^n + 1 / 1 - x$
$a_n - a_(n - 1) / a_(n - 2) + 1$
```

Хорошо:

```typst
$(x^2)/(1 - x)$
$(1 - x^(n + 1))/(1 - x)$
$(a_n - a_(n - 1))/(a_(n - 2) + 1)$
```

Если сомневаешься, ставь скобки. Лишние скобки лучше, чем съехавший PDF.

## 5. Индексы и степени

Если индекс или степень длиннее одного символа, используй скобки.

Плохо:

```typst
$a_n - 1$
$x^n + 1$
$2^n - 1$
```

Хорошо, если нужен именно индекс или степень:

```typst
$a_(n - 1)$
$x^(n + 1)$
$2^(n - 1)$
```

Для рекуррентных соотношений:

```typst
$a_n = 2 a_(n - 1) + a_(n - 2)$
```

А не:

```typst
$a_n = 2 a_n-1 + a_n-2$
```

## 6. Функции и ошибка с `$f_n(x)$`

Если речь про последовательность функций, лучше писать с пробелом между именем функции и аргументом:

```typst
$F_n (x)$
```

Так видно, что это `n`-я функция `F`, взятая в точке `x`.

Различай записи:

```typst
$a_n$          // n-й член последовательности
$f(x)$         // функция f от x
$f_n (x)$      // n-я функция из последовательности функций
$f_(n(x))$     // индексом является n(x)
$f(n, x)$      // функция двух аргументов
```

Если может возникнуть двусмысленность, один раз поясни словами:

```typst
Здесь $F_n$ — это функция, а $x$ — её аргумент.
```

После этого используй `$F_n (x)$`.

## 7. Начальные условия

Не пиши странные индексы-кортежи, если речь о нескольких начальных значениях.

Плохо:

```typst
$a_(0, 1, 2) = 3, 2, 6$
```

Хорошо:

```typst
$(a_0, a_1, a_2) = (3, 2, 6)$
```

Или:

```typst
$a_0 = 3$, $a_1 = 2$, $a_2 = 6$.
```

## 8. Длинные цепочки вычислений

Не запихивай слишком длинный вывод в одну строку. Если выражение длинное, разбивай.

Можно так:

```typst
$
A(x) = 1 + 3x + 5x^2 + dots
quad => quad
A(x) = (1 + x)/(1 - x)^2
$
```

Для многострочного вывода лучше использовать несколько коротких блоков или текст между формулами. Не надо делать огромный нечитаемый блок.

## 9. Текст внутри формул

Не пиши длинный русский текст внутри `$...$`.

Плохо:

```typst
$
a_n = 2^n - 1, где n это количество элементов
$
```

Хорошо:

```typst
Получаем $a_n = 2^n - 1$, где $n$ — количество элементов.
```

Формула отдельно, объяснение отдельно.

## 10. Суммы, пределы, произведения

Пиши явно:

```typst
$sum_(k = 0)^n C(n, k) = 2^n$

$lim_(n -> infinity) a_n/a_(n - 1) = sqrt(3)$

$prod_(i = 1)^m (1 - x^i)$
```

Если нижний индекс сложный, бери его в скобки:

```typst
$sum_(0 <= k <= n) a_k$
$sum_(S subset.eq [n]) (-1)^(|S|) |N(S)|$
```

## 11. Обозначения

- Все математические обозначения пиши в `$...$`: `$n$`, `$k$`, `$L$`, `$q_0$`, `$Sigma$`, `$epsilon$`.
- Не оставляй голые `n`, `k`, `L`, `q0` в обычном тексте, если это математические объекты.
- Для множеств и операций используй Typst-обозначения:

```typst
$in$
$in.not$
$subset.eq$
$backslash$
$emptyset$
$epsilon$
$Sigma^*$
```

## 12. Доказательства

Для доказательства от противного явно пиши:

```typst
Предположим противное: ...
...
Получили противоречие. Значит, ...
```

Для индукции обязательно разделяй базу и переход:

```typst
*База:* ...

*Переход:* ...
```

В конце полноценного доказательства можно поставить `$square$`.

Не ставь `$square$` после обычного вычисления или неформального рассуждения.

## 13. Как писать решение естественно

Лучше:

```typst
Здесь удобнее сначала посчитать все варианты без ограничения, а потом вычесть плохие.
```

Хуже:

```typst
В данном случае необходимо рассмотреть соответствующие варианты, которые позволяют получить требуемое количество допустимых объектов.
```

Лучше:

```typst
Порядок важен, повторения запрещены, значит используем $P(n, k)$.
```

Хуже:

```typst
Так как порядок элементов является значимым, а повторение элементов не допускается, необходимо применить формулу количества перестановок.
```

## 14. Частые опасные записи

Держи под рукой:

```typst
// Индексы
$a_(n - 1)$
$a_(i + 1)$
$x_(k + 2)$

// Степени
$2^(n - 1)$
$x^(k + 1)$
$(1 + x)^n$

// Дроби
$(n + k - 1)/(k - 1)$
$(1 - x^(n + 1))/(1 - x)$
$(a_n - a_(n - 1))/(a_(n - 2) + 1)$

// Функции
$F_n (x)$
$f_(n(x))$
$f(n, x)$

// Начальные условия
$(a_0, a_1, a_2) = (3, 2, 6)$
```

## 16. Финальный чеклист перед выдачей `.typ`

Проверь:

- короткие формулы не вынесены в отдельные блоки без причины;
- длинные дроби имеют скобки вокруг числителя и знаменателя;
- индексы вида `n - 1` записаны как `_(n - 1)`;
- степени вида `n + 1` записаны как `^(n + 1)`;
- функции из последовательности записаны как `$F_n (x)$`, если это именно функция от `x`;
- нет точек внутри блочных формул;
- нет голых математических обозначений вне `$...$`;
- нет одинаковых начал у всех пунктов;
- нет канцелярита типа «данный», «соответствующий», «является» без необходимости;
- нет слишком длинных строк формул, которые уедут за край PDF;
- `\\` и `#pagebreak()` используются только там, где реально нужны.

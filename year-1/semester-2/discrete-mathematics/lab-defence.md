# Problem 1 — Language Zoo

**Что делали:**  
Проверяли принадлежность слов языкам, операции с языками и классификацию по иерархии Хомского.

**Что помнить:**

- (\Sigma^*) — все конечные строки над алфавитом, включая (\varepsilon).
    
- (L^2 = L \cdot L) — склейка двух слов из (L).
    
- (L^*) — ноль или больше повторений.
    
- (L^+) — одно или больше повторений.
    
- (\overline L = \Sigma^* \setminus L).
    

**Ключевые языки:**

- `contains 010` — важно наличие подстроки.
    
- (a^n b^m) — сначала все `a`, потом все `b`, причём хотя бы одна `a`.
    
- (|w|) prime — важна только длина.
    
- (w#w) — слева и справа от `#` одно и то же слово; `#` подходит, потому что (w = \varepsilon).
    

**Иерархия Хомского:**

```txt
Type 3 — Regular
Type 2 — Context-Free
Type 1 — Context-Sensitive
Type 0 — Recursively Enumerable
```

Главное:

- (a^*) — regular.
    
- (a^n b^n) — context-free, нужен стек.
    
- (a^n b^n c^n) — context-sensitive.
    
- HALT — recursively enumerable, но undecidable.

# Problem 2 — Regular Expressions

**Что делали:**  
Описывали языки по regex, считали число слов длины (\le 5), потом писали regex по описанию языка.

**Что помнить по символам:**

```txt
ab       concatenation
a|b      либо a, либо b
a*       0 или больше повторений
a+       1 или больше повторений
a?       0 или 1 раз
[abc]    один символ из a,b,c
[^a]     любой символ алфавита, кроме a
```

**Главные моменты:**

- `ab*` даёт `a`, `ab`, `abb`, …
    
- `a+b?c` — одна или больше `a`, потом optional `b`, потом `c`.
    
- `[abc]*[cd]*` — после первого `d` больше не может быть `a` или `b`.
    
- `d(a|bc)*` — после `d` идут блоки длины 1 (`a`) или 2 (`bc`).
    
- “No two consecutive 1s”:  
    [  
    (0|10)^*1?  
    ]
    
- “Every 1 is immediately followed by 0”:  
    [  
    (0|10)^*  
    ]
    

**Главная защита:**  
Нужно уметь словами объяснить, почему regex запрещает или разрешает определённые строки.

# Problem 3 — DFA Construction

**Что делали:**  
Строили DFA для разных языков и доказывали корректность автомата для делимости на 3.

**DFA:**

[  
A = (Q, \Sigma, \delta, q_0, F)  
]

- (Q) — состояния.
    
- (\Sigma) — алфавит.
    
- (\delta) — переходы.
    
- (q_0) — старт.
    
- (F) — accepting states.
    

**Детерминированность:**  
Из каждого состояния по каждому символу есть ровно один переход.

**Автоматы:**

1. **Ends with `101`**  
    Состояния хранят, какой суффикс уже совпал с префиксом `101`.
    
2. **Odd number of 1s and even number of 0s**  
    Нужно помнить две чётности: нулей и единиц. Всего 4 состояния.
    
3. **Binary number divisible by 3**  
    Состояния — остатки по модулю 3.  
    Приписали бит (b):  
    [  
    val(wb) = 2val(w) + b  
    ]  
    Переход:  
    [  
    r_i \to r_{(2i+b)\bmod 3}  
    ]
    
4. **No `00`, no `11`**  
    Нужно помнить последний символ. Если повторился тот же символ — dead state.
    

**Готовый DFA во второй части:**  
Он принимает строки, заканчивающиеся на `ba`.

# Problem 4 — Powerset Construction

**Что делали:**  
Переводили NFA в DFA через Rabin–Scott powerset construction.

**Главная идея:**  
Состояние DFA — это **множество возможных состояний NFA**.

Если NFA может быть одновременно в нескольких состояниях, DFA хранит всё это множество.

**В задаче:**  
NFA распознавал строки, содержащие `010` как подстроку.

Regex:

[  
(0|1)^_010(0|1)^_  
]

**Что помнить:**

- Начальное состояние DFA: ({q_0}).
    
- Переход по символу — объединение всех переходов из состояний множества.
    
- Принимающее состояние DFA — любое множество, содержащее accepting state NFA.
    
- Теоретически было (2^4 = 16) состояний, но достижимы только 6.

# Problem 5 — Kleene’s Theorem

**Что делали:**  
Показывали обе стороны теоремы Клини:

```txt
Regex -> ε-NFA  через Thompson construction
DFA -> Regex    через Kleene algorithm
```

## Thompson construction

Для regex:

[  
(0|01)^*1  
]

строили (\varepsilon)-NFA.

**Что помнить:**

- Для `|` делается разветвление через (\varepsilon).
    
- Для конкатенации финал первого автомата соединяется со стартом второго.
    
- Для `*` добавляются новый старт и новый финал, плюс переходы:
    
    - войти внутрь;
        
    - пропустить всё;
        
    - повторить;
        
    - выйти.
        

Потом считали (\varepsilon)-closure.

(\varepsilon)-closure состояния — все состояния, достижимые только по (\varepsilon)-переходам, включая само состояние.

## Удаление ε-переходов

Формула:

[  
\delta'(q,a)=E(\delta(E(q),a))  
]

После этого был упрощённый plain NFA.

## Kleene algorithm

Это алгоритм получения regex из DFA через динамику:

[  
R^k_{ij} =  
R^{k-1}_{ij}  
\cup  
R^{k-1}_{ik}(R^{k-1}_{kk})^*R^{k-1}_{kj}  
]

Смысл:

> (R^k_{ij}) — regex для всех путей из (i) в (j), где промежуточные состояния можно брать только из первых (k) состояний.

В задаче итоговый язык автомата:

[  
(0|1)^*01  
]

то есть слова, заканчивающиеся на `01`.

# Problem 6 — Pumping Lemma

**Что делали:**  
Доказывали нерегулярность языков через pumping lemma.

**Формулировка:**

Если (L) regular, то существует pumping length (n), что любое длинное слово (w\in L) можно разбить:

[  
w = xyz  
]

так что:

```txt
|xy| <= n
y != ε
xy^i z ∈ L для всех i >= 0
```

**Типовая схема доказательства нерегулярности:**

1. Предположим, что язык regular.
    
2. Берём pumping length (n).
    
3. Выбираем специальное слово (w).
    
4. Рассматриваем любое разбиение (xyz).
    
5. Показываем, что (y) лежит в контролируемой части.
    
6. Берём (i = 0) или (i = 2).
    
7. Получаем слово вне языка.
    
8. Противоречие.
    

**Языки:**

- (0^n1^{2n}) — ломается баланс 0 и 1.
    
- Палиндромы — ломается симметрия.
    
- (ww) — ломается равенство половин.
    
- (1^{n^2}) — после накачки длина попадает между квадратами.
    

**Weak vs full pumping lemma:**

Главная мысль:

> Без ограничения (|xy|\le n) можно выбрать (y) удобно, например через границу `0^n1^n`.  
> Полная версия заставляет (y) лежать в первом блоке нулей, и тогда противоречие неизбежно.

# Problem 7 — Myhill–Nerode

**Что делали:**  
Доказывали нерегулярность через бесконечно много различимых строк и строили минимальные DFA через классы эквивалентности.

**Определение:**

[  
x \equiv_L y  
]

если для любого хвоста (z):

[  
xz\in L \Longleftrightarrow yz\in L  
]

То есть (x) и (y) имеют одинаковое будущее поведение.

**Главная теорема:**

> Язык regular iff число классов Myhill–Nerode конечно.  
> Число классов равно числу состояний минимального DFA.

**Как доказывать нерегулярность:**

Найти бесконечное множество попарно различимых строк.

Примеры:

- Для (0^n1^n): строки (0^k), хвост (1^i).
    
- Для (ww): строки (0^k1), хвост (0^i1).
    
- Для палиндромов: строки (0^k), хвост (10^i).
    

**Минимальные DFA:**

- Ends with `01` — 3 класса.
    
- Odd number of `1`s — 2 класса.
    
- Length divisible by 3 — 3 класса.

# Problem 8 — Closure Properties

**Что делали:**  
Проверяли, какие утверждения о regular/non-regular языках верны.

**Что помнить:**

Regular languages closed under:

```txt
union
intersection
complement
difference
concatenation
star
reverse
```

**Ключевые ответы:**

1. Если (L) regular, то (L^R) regular — always true.  
    Разворачиваем переходы автомата, получаем NFA.
    
2. Если (L_1,L_2) non-regular, то (L_1\cup L_2) non-regular — depends.  
    Контрпример: (L) и (\Sigma^*\setminus L).
    
3. Если (L_1\cup L_2) regular и (L_1) regular, то (L_2) regular — depends.  
    Контрпример: (L_1=\Sigma^*), (L_2) non-regular.
    
4. Если (L_1L_2) regular, то оба regular — depends.  
    Контрпример: (L_2=\emptyset).
    
5. Если (L) regular, то ({w\mid ww\in L}) regular — always true.  
    Идея: слово (w) задаёт функцию переходов (f_w:Q\to Q), таких функций конечно много.
    

**Product construction:**

Для (L_1\cap L_2) строим автомат по парам состояний:

[  
(q,p)  
]

Переходы покомпонентные:

[  
\delta((q,p),a)=(\delta_1(q,a),\delta_2(p,a))  
]

Для intersection accepting, если оба компонента accepting.  
Для union accepting, если хотя бы один компонент accepting.

# Problem 9 — Context-Free Grammars

**Что делали:**  
Читали EBNF, описывали CFG, строили CFG и переводили грамматику в CNF.

**CFG:**

[  
G=(V,\Sigma,R,S)  
]

- (V) — переменные/nonterminals.
    
- (\Sigma) — terminals.
    
- (R) — productions.
    
- (S) — start variable.
    

**EBNF:**

- `<sign>?` — optional.
    
- `<digit>*` — любое количество цифр.
    

**Примеры языков:**

- integer без ведущих нулей:  
    [  
    [+-]?[1-9][0-9]^*  
    ]
    
- identifier:  
    [  
    [A-Za-z][A-Za-z0-9_]*  
    ]
    

**CFG:**

- (S\to 0S1|\varepsilon) даёт (0^n1^n).
    
- (S\to aSb|bSa|SS|\varepsilon) даёт равное число `a` и `b`.
    
- (S\to AB), (A\to aA|a), (B\to bB|b) даёт (a^+b^+).
    
- (S\to aSa|bSb|a|b|\varepsilon) даёт палиндромы.
    

**CNF:**

Chomsky Normal Form:

```txt
A -> BC
A -> a
```

Плюс иногда допускается:

```txt
S0 -> ε
```

если язык содержит пустую строку.

**Зачем CNF:**  
Для алгоритма CYK.

# Problem 10 — Turing Machines

**Что делали:**  
Трассировали TM, проектировали TM и классифицировали decidability.

**TM для (0^n1^n):**

Идея:

1. Найти левый неотмеченный `0`.
    
2. Зачеркнуть.
    
3. Найти соответствующую `1`.
    
4. Зачеркнуть.
    
5. Вернуться влево.
    
6. Если всё сопоставлено — accept.
    
7. Если порядок сломан или пары нет — reject.
    

**Design:**

1. (0^{2^n}):  
    Повторно делим число нулей на 2, зачёркивая каждый второй.  
    Если остался 1 — accept.  
    Если нечётное число больше 1 — reject.
    
2. (w#w):  
    Сравниваем символы слева и справа от `#` по одному, отмечая пары.
    

**Decidability:**

```txt
R       decidable
RE\R    recognizable but undecidable
neither neither RE nor co-RE
```

Ключевые примеры:

- “TM has exactly/fewer states” — decidable, синтаксическое свойство.
    
- “accepts within 1000 steps” — decidable, ограниченная симуляция.
    
- “accepts ε” — RE but undecidable.
    
- “language is infinite” — neither.
    
- “language equals Σ*” — neither.

# Problem 11 — Exact Counting vs Modular Counting

**Что делали:**  
Сравнивали точное равенство количеств и равенство по модулю.

## Closure proof

[  
L={0^i1^j\mid i\ne j}  
]

Нерегулярен, потому что:

[  
0^_1^_ \setminus L = {0^n1^n\mid n\ge0}  
]

Если бы (L) был regular, то разность тоже была бы regular. Но (0^n1^n) нерегулярен.

**Смысл:**

> (L) — это (0^_1^_) без диагонали (i=j). Closure выделяет скрытый нерегулярный язык.

## Modular counting

[  
L'={w\mid #a(w)\equiv #b(w)\pmod 2}  
]

Это regular, потому что надо помнить только остаток по модулю 2.

Для общего (m):

Состояния:

[  
q_0,\dots,q_{m-1}  
]

Инвариант:

[  
\delta^*(q_0,w)=q_k  
\Longleftrightarrow  
#a(w)-#b(w)\equiv k\pmod m  
]

Переходы:

```txt
a: +1 mod m
b: -1 mod m
```

Минимальность: строки

[  
\varepsilon,a,a^2,\dots,a^{m-1}  
]

попарно различимы.

# Problem 12 — Closure Game

**Что делали:**  
Разбирали ловушки замкнутости, HALF-language и homomorphisms.

## Closure traps

Главная мысль:

> Из нерегулярности языка часто нельзя автоматически получить нерегулярность после операции.

Примеры:

- (L) non-regular, но (L^2) может быть regular.
    
- (L) non-regular, но (L^*) может быть regular.
    
- (L_1,L_2) non-regular, но intersection может быть empty.
    
- (L_1) regular, (L_2) non-regular, но (L_1\setminus L_2) может быть regular.
    

## Mutual constraints

Если:

[  
L_1\cup L_2=\Sigma^*  
]

regular, но

[  
L_1\cap L_2={a^nb^n}  
]

non-regular, то:

- оба regular быть не могут;
    
- ровно один regular — могут;
    
- оба non-regular — могут.
    

## HALF(L)

[  
HALF(L)={x\mid \exists y,\ |y|=|x|,\ xy\in L}  
]

Если (L) regular, то (HALF(L)) regular.

Идея:

> После чтения (x) надо знать состояние автомата и множество состояний, из которых за (|x|) шагов можно дойти до accepting.

## Homomorphisms

Гомоморфизм заменяет буквы на фиксированные строки:

```txt
h(a)=01
h(b)=10
```

Главная теорема:

> Если (L) regular, то (h^{-1}(L)) regular.

Строим автомат, который на букве (a) симулирует исходный автомат на слове (h(a)).

# Problem 13 — Undecidability

**Что делали:**  
Rice’s theorem, diagonalization, reduction (HALT \le_m A_{TM}).

## Rice’s theorem

Любое нетривиальное семантическое свойство языка TM undecidable.

**Semantic:** зависит только от языка (L(M)), не от устройства машины.  
**Non-trivial:** есть машины, у которых свойство есть, и есть машины, у которых свойства нет.

Примеры:

- (L(M)) nonempty — undecidable.
    
- (L(M)) empty — undecidable.
    
- (L(M)) regular — undecidable.
    
- (M) has fewer than 100 states — decidable, не semantic.
    
- (M) halts on all inputs — undecidable, но Rice не применяется, потому что свойство не semantic.
    
- (L(M)) contains palindrome — undecidable.
    

## Diagonalization

Ошибка алгоритма с (k) шагами:

> Если машина не остановилась за (k) шагов, это не значит, что она не остановится позже.

При (k\to\infty):

> Симуляция распознаёт положительные случаи, но не даёт `NO` за конечное время.

Диагональная машина (D):

- если (M) останавливается на (\langle M\rangle), то (D) зацикливается;
    
- если (M) не останавливается на (\langle M\rangle), то (D) останавливается.
    

Запуск (D(\langle D\rangle)) даёт противоречие.

## Reduction

Доказывали:

[  
HALT \le_m A_{TM}  
]

По (\langle M,w\rangle) строим (M'):

1. игнорирует вход;
    
2. симулирует (M(w));
    
3. если (M(w)) остановилась, принимает;
    
4. если не остановилась, не принимает.
    

Тогда:

[  
\langle M,w\rangle\in HALT  
\Longleftrightarrow  
\langle M',\varepsilon\rangle\in A_{TM}  
]

Значит, если бы (A_{TM}) был decidable, то HALT тоже был бы decidable. Противоречие.

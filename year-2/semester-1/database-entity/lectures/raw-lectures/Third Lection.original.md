### **Физически**

Имеем **память** (линейно - адресуемое пространство), пока не важно с какой адерсацией.

### **Иерархическая модель данных**

Строим модель на примере билиотеки, имеем некоторое количество книг, которые мы хотим классифицировать, разбить на кластеры и т.п. 

Решаем одну из двух задач: разбиение по _классам эквивалентности_ или _классам толерантности_. 

Решение задачи разбиения на классы эквивалентности сводится к простому построению деревьев. 
_Пример._ Разбиение книг на жанры, поджанры и т.д. 

Но деревья - плохое решение, ведь при решении задачи таким образом у потомка должен быть лишь один родитель.

Переходим на пример дивизионной модели управления (как в бизнесе, ген. директор -> заместитель директора -> ...)


| изделие  | название | стоимость | ... |
| -------- | -------- | --------- | --- |
| <пример> |          |           |     |

| компонент | марка | вес | ... |
| --------- | ----- | --- | --- |
| <пример>  |       |     |     |

| деталь | марка | материал | ... |
| ------ | ----- | -------- | --- |
|        |       |          |     |

```
				 изделие
			    /       \
	   компонент         компонент
	  /         \
деталь           деталь
```

Деталь имеет **pointer** на родителя, который так же лежит в памяти (память линейна):

```cpp
stuct Item {
	pointer ItemOrigin;
	data;
};
```

### **Реляционная модель**

Вводим понятие отношения в виде плоской таблицы: 


| компоненты |          |       |     |     |
| ---------- | -------- | ----- | --- | --- |
| id         | название | марка | вес | ... |

| детали |          |       |     |        |     |
| ------ | -------- | ----- | --- | ------ | --- |
| id     | название | марка | вес | размер | ... |

Простраиваем отношение  Компонент  -> деталь: 

| компонент    | деталь    |
| ------------ | --------- |
| id_component | id_detail |
| 1            | 1         |
| 2            | 1         |

Почему это лучше: 

1. Нет **указателей**, мы физически **не ходим** по графу, по элементам
2. <... добавить ещё плюсов>

Чем хуже: 
Мы перекладываем ответственность за целостность данных на пользователя. 
_Пример._ Пусть color (integer) получается как: `'Black' = 1`, `'White' = 2` и т.д.
Тогда мы можем спокойно связывать, условно, id элемента и цвет <придумать пример с `SELECT`>

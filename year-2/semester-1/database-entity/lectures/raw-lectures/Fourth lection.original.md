### **Отношение**

Много лет люди упускали, что все данные в таблицах не просто представляют отдельные множества, а принадлежат одному общему множеству. Это идея стала ключевой в идее Реляционной модели БД. 

_Прим._ 

| студент |     |          |
| ------- | --- | -------- |
| ИСУ     | ФИО | N группы |


| группа   |          |       |
| -------- | -------- | ----- |
| N группы | Староста | Баллы |

Простраиваем связь Студент -> Группа. 

_Опр._ Кортеж - строка таблицы
_Опр._ Схема отношения - строка с наименованием атрибута
_Опр._ Домен - множество допустимых значений для аттрибутов 
_Опр._ Поле - ячейка в таблице
_Опр._ Степень отношения - количество атрибутов

Пусть задано некоторое количество доменов $D_1, D_2, D_3, ...$, где $R = d_1, d_2, d_3, ..., d_i, \space d_i \in D_i$

IBM быстро поняли, что реализовать математические абстракции Кодда реализовать в инженерном плане нельзя, поэтому они поупрощали его систему. 

<Про то, что SQL **по мотивам** работ Кодда, а не "По Кодду">

Например, IBM реализовали в SQL пару вещей, которые противоречили работам Кодда:

- Каждый элемент должен быть атомарен <пример с `ILIKE` и `LIKE` и о делимости одного символа от элемента>
- В отношении каждый Кортеж **уникален** <пример с привязке `DISTINCT` к `SELECT`>
- Уникальность имени **отношения** в Реляционной схеме
- Уникальность имени **атрибута** в пределах отношении
- Значение атрибута берутся из одного и того же Домена <пример с тем, что мы можем взять за Домен номера группы с таблице Student номера групп из таблицы Groups, а так же проблема `NULL` и его кодирование в типах данных SQL, отсюда костыль `IS NULL / IS NOT NULL 
-  Порядок следования атрибутов и порядок следования кортежей ***не имеют значения***

_Опр._ Суперключ - атрибут или множество атрибутов, единственным образом идентифицирующий кортеж.

Из свойств отношений следует, что любое ... является суперключом. <Пример суперключа>

_Опр._ Потенциальный суперключ - суперключ, который не содержит подмножества, так же являющегося суперключом данного отношения <пример>
_Опр._ Первичный ключ (Primary key) - потенциальнй ключ, выбранный для уникальной идентификации <чёто там, после пример>
_Опр._ Внешний ключ - атрибут или множество атрибутов внутри отношения, которое соотв потенциальному ключу некоторого, может быть, потенциального отношения
_Опр._ Ссылочная целостность - если в отношении присутствует внешний ключ, то значения внешнего ключа должно либо соответствовать значению внешнего ключа, либо внешний ключ состоит из `NULL` значений
